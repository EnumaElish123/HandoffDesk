## 用户现在的操作

Linux 源码安装可使用 `python scripts/install.py`，按结束时给出的命令打开阅读器。既有源码开发环境继续用原入口即可。首次 hooks 信任仍由宿主管理；配置文件准备好不等于自动调用已通过验证。

| 操作 | 按键/命令 |
| --- | --- |
| 搜索、项目、任务 | `/`、`p`、`t` |
| 未读、清空筛选 | `u`、`x` |
| 阅读详情/返回 | Enter、Esc |
| 附件全文/元信息 | `f` → Enter；`m` 显示完整位置与用途 |
| 附件翻页/复制路径 | PgUp/PgDn、Ctrl+C；本机剪贴板取决于终端能力 |
| 导出/复制续接提示 | `e`、`y` |
| 更新历史/加载更多 | `r`、`n` |
| 接入诊断/帮助/退出 | `c`、`?`、`q` |
| 非交互终端 | `handoffdesk feed`，然后 `handoffdesk read RECORD_ID --markdown` |
| 可读诊断 | `handoffdesk doctor --human --probe` |

Agent 在新上下文先发现已有任务，正常继续使用新轮次；完整提案按 checkpoint 取得。用户要求暂停时仍保持暂停，只有明确恢复记录后才使用 `--resume-recording`。每次保存后的回执汇报仍独立于用户已读状态。

### 已跑通的实际流程

- 独立源码安装、`--no-connect` 重装、默认接入重装、移动到中文空格安装目录：状态 ID、目录和历史记录 ID 保持；用户改过的命令保留；旧安装的移除操作不删除新安装命令。
- 最终 Skill 前向试用：从无上下文发现任务、保存、模拟汇报、确认、结束，再丢弃 session 引用仅凭 cwd 找回；同名独立新建、跨宿主工作线续接均有回归覆盖。
- 12 条待汇报回执分 3 页完整恢复；已替换失败提案在历史第 5 页仍可取得原文。模拟汇报均标明测试性质，不冒充真实消息送达。
- 实际 tmux：80×24 读详情和附件，PgDn 翻页，缩至 60×18 仍读正文，确认导出，`q` 正常退出 0。
- 受控 Textual 交互：小屏搜索空结果不保留旧详情；55 条长标题历史加载后追加 10 条，选中项和视觉位置保持；附件 80×24、60×18 均有至少 10 行正文；导出拒绝覆盖和取消、模态中刷新、快速退出均检查。
- 完整包在源码外的新独立环境安装运行；移动后的便携包在 PATH 不含 Python 的环境保存、发现、继续及阅读记录。通过空 `PYTHONTZPATH` 验证命名时区不依赖系统时区库。

### 输出体积与旧历史性能

同一口径：每阶段正文 1,279 字符、50 条已汇报历史。旧 `status` 标准输出为 **535,774 字节**；新版公开 `status` 与 `resume` 各 **5,424 字节**，低于方案的 8 KiB 目标。完整正文仍可按单条读取，不是删除历史。

独立审查发现旧格式记录搜索会逐条重新连接 SQLite。改为同一查询连接快照后，10,000 条旧记录的无匹配搜索从约 **3.84 秒降到 0.71 秒**；项目名命中约 160 ms，附件名命中约 192 ms。以上是本机单次测量，不是跨机器性能保证。

### 复核中一并修正的问题

- 跨程序目录升级时，命令仍指向旧安装；现仅在旧登记、清单和内容摘要共同证明所有权后转交。
- 系统没有 IANA 时区库时，有效的 `Asia/Shanghai` 被误报为无法识别；增加 `tzdata` 回退与便携收集，并测试空系统搜索路径。依据 [Python 官方时区数据说明](https://docs.python.org/3/library/zoneinfo.html#data-sources)。
- 附件返回列表后复制其他高亮项曾沿用上个路径，现按当前页面与选中项复制。
- 模态样式作用域、小屏 resize、关闭时后台回调和诊断页首次挂载已加入回归检查。
- 原有一个测试要求全新 `list` 报初始化错误，与 L13 的新行为冲突；改为对确实需要配置的 `show` 检查错误提示，全新空列表另有回归验证。

## R5 环境验收的实际边界

14 项产品改动均已实现。R5 的远程/真实宿主验收尚有以下环境条件，不能计为通过：

1. 本机 Codex 命令包装器指向不存在的 `/usr/local/bin/codex`，无法从该入口完成真实宿主 hooks 信任与自动触发。诊断如实显示入口启动失败；没有修改真实 Codex 配置或制造已验证状态。
2. 已核对本机 SSH 主机公钥后尝试连接，当前账户认证被拒绝；另用本机临时 SSH 实例、独立临时密钥尝试仍无法认证，已关闭实例并清理临时密钥。真实 tmux 已通过，SSH 跨主机、物理终端及剪贴板送达仍未验证。
3. 实际系统仍是现有 Ubuntu 20.04 主机；新虚拟环境、隔离 HOME 和移动便携包不等于干净发行版。现有 CI 会运行新增回归与安装检查，但本轮未推送，所以不能声称远程 CI 或其他发行版通过。

补验时应使用可工作的 Codex 宿主和可登录 SSH 目标，运行一次真实项目任务，验证首次信任前后、权限不足、暂停/中断、逐次汇报、resize 和剪贴板支持/不支持两种结果。代码已提供相应状态与恢复入口，具体宿主授权不能由安装器自动冒认。
