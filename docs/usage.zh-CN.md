# HandoffDesk 使用手册

0.10 默认使用 Windows 本地 Web 阅读器和 Linux TUI，安装见 [中文 README](../README.zh-CN.md)，自动接入见 [低配置接入](agent-first.md)。新阅读器可筛选项目、任务、未读，搜索标题、正文、验证说明、文件名称/路径或完整回执编号；选择阶段查看完整说明与附件，支持预览、复制和导出。搜索不读取附件正文，也不匹配内部协议字段。新记录自动更新列表而保留当前详情。

Windows 阅读器自动展示最新记录时不会标记已读，主动选择才确认阅读；详情底部可“标为未读”撤销。手动刷新会更新当前附件状态并保留阅读位置。附件缺失或操作失败显示在对应文件旁，不表示连接中断，修复文件后可原地重试。验证状态是记录者提供的报告，工具不会自行执行其中的测试。

导出默认使用“日期-项目-标题-短编号.md”，保留中文并处理 Windows 无效字符；原生桌面由系统对话框决定最终保存位置，浏览器通过下载保存。导出包含记录与文件清单，附件内容不会自动嵌入 Markdown。

Linux 按上下键或 j/k 选记录、Enter 阅读、Esc 返回、/ 搜索、p 选项目、f 看附件、u 切换未读、n 加载更早记录、q 退出。输入框内字母正常输入；SSH 的文件位置属于服务器，剪贴板能力由终端决定。

以下章节保留为原有工作线、节点、草稿和来源复核的高级参考。相关旧窗口操作请用 `handoffdesk legacy-desktop`；默认 Web 阅读器以阶段阅读为主。Agent 记录协议仍为 1。示例 ID `alpha` 和路径应替换为实际值。

## 1. 理解项目、工作线和节点

项目对应一组你明确授权读取的根目录。工作线把同一项目中的不同任务分开，例如“功能开发”和“文档整理”；它们分别保留交接、计划、来源快照、草稿和复核。

节点是查看文件的进度位置：

| 节点 | 文件来自哪里 | 适合什么场景 |
| --- | --- | --- |
| 当前工作 | 当前工作线已登记来源、材料入口及手动关联 | 查找这条工作线当前使用的材料 |
| 历史交接或计划 | 保存该记录时的文件清单，以及后来对该节点做的关联调整 | 回看一个具体阶段 |
| 自建节点 | 创建时选定的文件入口及之后的关联 | 收好一次实验、一次交付或一次复核的材料 |

文件清单记录位置和用途，同一路径的原文件之后仍可能变化。新记录保存文件大小、修改时间，普通文件不超过 1 MiB 时同时保存内容指纹；大文件只按元信息比较，旧记录没有版本基线时明确显示未知。目录不会递归计算指纹。原始历史正文不会因为文件变化而被改写。

Windows 阅读器中可对普通文件明确点击“保存证据副本”：将操作当时的当前内容保存到工具数据目录 `evidence/` 并关联到该记录，每个文件最多 10 MiB，相同内容重复保存会复用已有副本。副本标注来源、保存时间和内容指纹，**不是原记录时的历史快照**，也不是防篡改存储。源文件保持不变；副本之后被修改会提示变化。移除关联仍遵循只移除引用的语义，不删除原件或证据副本。更大文件或完整项目仍应使用自己的版本管理和归档流程。

## 2. 首次连接自己的项目

若还未初始化，可以直接登记一个现有目录：

```sh
python -m handoffdesk init --project alpha --name "我的项目" --root /absolute/path/to/your-project
```

已初始化演示项目或其他项目时，用 `project add`：

```sh
python -m handoffdesk project add alpha --name "我的项目" --root /absolute/path/to/your-project
python -m handoffdesk list --json
python -m handoffdesk legacy-desktop
```

注册根目录不会自动递归扫描整个项目，也不会自动修改项目内的 `AGENTS.md`。来源和材料入口可在状态目录的 `config/projects.json` 中明确登记，详见 [配置说明](configuration.md)。桌面中新建工作线可以将不同任务分开。

## 3. 每次继续工作的流程

1. 在侧栏选择项目，再选择本次工作的工作线。
2. 阅读首页的最近进展、下一步和阻塞。留意作者与验证说明，以及来源是否出现变化。
3. 需要核对依据时，到来源页查看登记文件、读取时间与原始记录；它们表示保存时的观察，不代表任务或服务现在仍在运行。
4. 用“本次文件”或“节点文件”进入文件清单，打开当前阶段需要的材料。
5. 工作完成一个有意义的阶段后，通过 Agent 记录接口保存，或在桌面“留下交接”；尚未执行的内容使用“设置下一步”。

“继续工作”会打开所选材料；它不会启动开发脚本、训练任务或后台服务。

## 4. 按进度节点管理文件

### 查看和查找

进入“节点文件”后，在节点选择器中选当前工作、历史交接或自建节点。列表显示文件名称、用途和状态；选中一行可查看完整路径。查找框可按名称、用途或路径筛选，按 Esc 可清空查找。目录作为一个入口展示，不自动展开内部内容。

首页“本次文件”进入最新记录的清单；在历史页选中一份记录，再点“查看节点文件”，进入该历史节点。切换节点后先核对节点标题和工作线，避免把其他阶段的附件当成本次产物。

### 关联文件与文件夹

点击“关联文件”，可一次选择多个文件，并填写用途。点击“关联文件夹”保存一个目录入口。建议用途写清“为什么下一位需要它”，例如“本阶段结果及已知限制”，比“文件1”更方便续接。

点击“新建节点”，填写阶段名称和说明。创建框中的“带入当前工作线已登记的文件”会把当前材料带入；若只想保存某次交付的少量文件，可以取消勾选，创建后再添加。

Agent 保存的阶段清单只包含这次提交的 `files`，不会自动混入其他节点的文件。

### 打开、定位与复制路径

选中文件后使用“打开”“资源管理器/文件管理器”“复制路径”。双击文件也可打开，按钮会随文件类型和状态调整。

- 普通文档使用系统默认程序。修改文档属于该外部程序的行为，应按自己的工作流程保存。
- 脚本按文本查看，工具不会执行它；Ubuntu 使用内置只读查看器，Windows 使用文本程序。
- 模型、可执行文件及无法安全识别的类型优先定位目录。
- 桌面文件管理器支持目标选择时会选中文件；否则打开父目录。

找不到文件、没有权限或当前位置不属于本机时，先查看状态和完整路径。服务器 CLI 可查询路径；打开程序需要该机器的图形会话。

### 文件移动、用途修改和移除

在“更多”中查看详细信息、修改用途或重新定位。文件搬家后，选择新的实际位置；原用途会保留。节点名称及说明也可通过“更多”修改。

“移除关联”只移除本节点中的入口，保留磁盘上的原文件。某个历史记录的正文和版本保留；对节点文件的调整以本地关联状态体现。重新定位并不移动原文件，也不自动迁移其他节点中相同路径的记录。

## 5. 让 Agent 保存，自己查看

Agent 使用 [记录接口](agents.md)，填写明确的项目和工作线。桌面和 Agent 指向同一数据目录时，窗口会检测到外部新进度并显示“有新进度，点击更新”。点击后读取最新记录，正在编辑的草稿会保留。

首页展示记录作者及“报告验证”状态。`passed` 表示记录者报告已通过的检查，工具不会自行重新执行这些检查；范围和未验证事项应写入说明。读取到某份历史状态为 running，也不等于当前进程仍在运行。

## 6. 来源刷新、变化复核和工作材料

配置中明确登记的来源支持文本/Markdown、JSON 字段和可选的只读 Git 状态。刷新读取这些来源，不运行其中的命令。大文件只在支持的边界内读取或拒绝读取，不会为了文件清单扫描整个目录。

来源变化后，可查看新旧观察并决定：沿用已确认的下一步，或根据变化调整计划。“已复核，沿用下一步”应在实际读过变化后使用；复核不会把以前的证据替换为新证据。

“绑定到下一步”把选中的已登记材料作为当前工作线的常用入口。它与某次 Agent 提交的阶段文件清单分别保存。需要把任意本机文件归入一个阶段时，使用节点文件关联。

## 7. 计划、交接、草稿与历史

“设置下一步”只记录计划，不生成已完成项。“留下交接”填写实际进展、下一步和阻塞。导入助手总结先形成草稿，应核实内容后再保存；工具不会把自由文本自动当成已验证事实。

历史页可查看此前版本；“恢复所选内容为新版本”会追加一份记录，而不是抹掉之后发生的历史。多进程并发保存发生冲突时，先查看双方内容再合并，不能只增加版本号覆盖别人。

## 8. 命令查询与摘要导出

从源码目录运行，或安装后将前缀换成 `handoffdesk`：

```sh
python -m handoffdesk list --json
python -m handoffdesk worklines alpha
python -m handoffdesk show alpha --workline default --json
python -m handoffdesk refresh alpha --workline default --json
python -m handoffdesk history alpha --workline default
python -m handoffdesk nodes alpha --workline default
python -m handoffdesk files alpha --node record:default:1
python -m handoffdesk export alpha --workline default --format markdown
```

`record:default:1` 仅是第一条记录的格式示例，实际使用保存回执或 `nodes` 返回的编号。导出会在工具数据目录中生成本机摘要，内容可能含真实路径和敏感描述，分享前应审阅。

## 9. 数据、备份和多台机器

状态目录位置、指定目录方法和旧版迁移见 [配置与迁移](configuration.md)。数据库是本地 SQLite，可能包含进度正文、作者、文件位置、来源节选、历史和草稿；不只是附件路径。

备份配置和数据库不等于备份项目文件。跨机器使用需要分别准备配置、记录数据与实际文件；根目录映射仅帮助当前来源定位，历史位置保留原样，可按节点重新定位。不同机器之间没有自动同步或冲突合并服务。

## 10. 常见问题

| 现象 | 处理 |
| --- | --- |
| 提示未初始化 | 先运行 `init`；已有安装时检查 `--app-dir` 或 `HANDOFFDESK_HOME` 是否一致 |
| Agent 已保存，窗口没有进度 | 核对机器、用户、状态目录、`--data-dir`、项目和工作线，再点击新进度提醒 |
| 命令查询成功，桌面打不开 | 检查同一 Python 的 Tk 和当前图形会话；服务器无显示时使用 CLI |
| 节点文件不存在 | 核对是否在另一台机器、是否移动；准备真实文件后重新定位 |
| 来源缺失 | 配置登记的相对路径可能不存在；检查根目录和来源设置后刷新 |
| 保存退出码 3 | 发生版本冲突，读取最新上下文并比较内容，见 Agent 指南 |
| 想清空试用记录 | 使用独立试用状态目录；确认目录后自行移除试用目录，勿删除正式数据 |

功能问题反馈时提供操作步骤、版本、系统和去除个人信息的错误输出，见 [贡献说明](../CONTRIBUTING.md)。
