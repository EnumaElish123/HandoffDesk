# 本地数据与公开发布边界

HandoffDesk 保存本机项目的进度和文件位置，不需要云账号，也不提供网络服务器或自动遥测。读取和写入范围由本机配置及命令选择决定。

## 哪些信息会保存

状态目录中的配置和数据库可能包含：

- 项目名称、根目录、来源相对路径、材料入口和工作线定义。
- 计划与交接正文、阻塞、作者及可选会话编号、记录者报告的验证情况。
- 文件与目录的绝对路径、用途、阶段关联、历史及本地修改。
- 登记来源的读取时间、元数据、有限文本/JSON 节选和 Git 状态观察。
- 草稿、复核、界面偏好，以及导出的本机摘要。

这些信息以本地文件和 SQLite 保存，应用不提供内容加密或多用户权限管理。使用操作系统账户与文件权限控制访问；不要把状态目录放入会自动公开同步的位置。工具不会替你审查源文档是否含密钥或敏感数据，登记来源时应控制范围。

## 对项目文件的操作

来源读取和文件关联不会修改业务文件。关联保存位置与用途，不复制整个文件，也不递归扫描所关联文件夹。移除关联保留原文件，重新定位只更新引用位置。

点击普通文档会调用系统默认应用；随后在外部应用中编辑或保存是该应用的行为。脚本作为文本打开，工具不执行脚本；模型和未知文件类型优先定位目录。明确配置的网页入口可能打开浏览器，但应用不会把数据库自动上传到网页。

文件路径、来源节选和 Markdown 导出本身可能泄露账户、项目名或研究内容。报告问题前应检查错误文字和截图，避免直接附完整数据库或配置。

## 仓库应包含什么

公开仓库只应包含程序源码、通用示例、测试、文档、许可证和发布脚本。下列个人状态与生成物应保留在本机并由忽略规则排除：

- `cards.sqlite3` 及 SQLite WAL、SHM、journal 文件，真实记录或数据导出。
- 实际 `config/projects.json`、`roots.local.json`、含本机路径的配置副本。
- 个人备份、日志、截图、验收证据、历史发行包和开发工作目录。
- 凭据、SSH 密钥、令牌、环境文件、私有服务地址。
- 捆绑的本机 Python 环境、缓存、虚拟环境与下载内容。

`config/projects.example.json` 和 Agent 模板只含通用占位符。它们不是从个人配置删几个字段得到的副本。测试中的通用 Windows/POSIX 路径用于安全边界和跨系统回归，不指向真实用户资料。

忽略规则只影响尚未跟踪的文件，不能删除 Git 历史中的内容。发布前同时审阅暂存内容、提交历史和发行包文件清单，确认没有个人状态；不要用 `git add -f` 跳过隐私排除。如果敏感信息已经公开，应先撤销受影响凭据，再按托管平台流程处理历史。

## 安全反馈

普通功能问题可提交脱敏 issue。涉及凭据、任意文件写入或其他敏感漏洞时，遵循 [SECURITY.md](../SECURITY.md)，避免将利用材料和个人资料直接公开。
